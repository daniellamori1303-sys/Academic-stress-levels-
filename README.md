Semester Long Project Overview: 

	The students will complete a group project to gain experience in analyzing real-world data. The primary goal is to learn how to complete a data-focused project from start-to-finish, applying the skills and tools we have learned in class. A secondary (but important!) goal is for students to have a fully-formed project they can use in their portfolios/resumes. 

	As given in the syllabus, the semester project is worth 25% of the student’s total grade. 

	Team work should be distributed evenly. Each team member should take part in writing the papers and slides, writing the code/ exploring the data, and giving the presentation. 

Reminder: use of Gen AI tools such as Chat, Claude, etc are not allowed. It is especially bad to use them for the “what’s missing” and “what kind of questions could you answer” sections. (They are generally bad at it; and those are the exact things you — a beautiful, unique human with incredible potential — need to practice and develop skills in.) 

Part 1: Proposal (due Thursday Oct 8 at 9am)

Goal: form teams around a broad project idea and begin to collect/explore data. 

Deliverables:
One page proposal, one submission per team
Include team name and member names (2-3 people per group)
Include ~½ page description of your area of interest/curiosity. Include why you are interested in this and how you think data could help.
What kinds of questions could you answer? (Put another way: what “story” might you tell with this data?)
See class slides from Oct 1
Include ~½ page of where you found data (including the specific site, url, and/or link.) 
Include any basic caveats / limitations of the data (you will include more in the data dictionary). This should include a discussion of what is missing from the dataframe itself – what relevant rows and columns might not be in the dataframe at all? 
Notes: 
Data must have at least 100 rows and 8 columns and come from a reputable source. You can also join data from different sources, a technique we’ll learn later in class. See me if any questions.
Make sure you keep a copy of your original csv! I may request to review it if the link you used to grab it changes. 
Deliverable Format: Turn in a .pdf or .docx file named TeamNameProposal.doc [.pdf] 
To determine limitations of the data, include an .ipynb file with some exploratory data analysis. 
This should include everything you did in case study #1, which includes:
Think about what is not even in the dataframe. Include a separate comment cell about what rows and columns may not have made it into the dataframe, and why.
Write at least 10 lines of code exploring what is in the dataframe. This could include the size of the dataframe, unique values, etc. Suggest using the “describe” command, and/or value_counts(). Add comments to describe your code.
Explore missing values within the dataframe itself. Write code & comments to explore what values are missing. (Include this in your data dictionary, see below.)
Include a comment cell on what impact missing data (including what’s not in the dataframe at all, and what values are missing) would have on your analysis. How might your data be skewed? This should be at least three lines. 
Make at least 5 different plots of 2 different types. 
If you write any code to do any analysis or exploration of possible data stories, include it here also. 
You will also need to include:
Any exploration needed to create the data dictionary (see below)
Include comments throughout explaining your work
(If you are working with a large data set and want help efficiently looping through columns, come to OH and I can help.) 
Deliverable Format: an .ipynb named TeamNameProposal.ipynb
A spreadsheet or table containing something we’ll call a “data dictionary”. This includes:
For each column you’re planning to use, include the name, the data type, what you think it represents, the range (min/max) for numerical data or common values for categorical data. Include any issues with it.
Include any missing or obviously buggy data (meaning incorrect or wrong) 
If you’re not going to be using some of the columns, briefly note why
See dictionary example here for the kc_house_data. (The example link should be for view only, please make your own copy.) 
Deliverable Format: You should turn in either an excel file (named TeamNameDataDictionary.xlsx) or a working link to a google doc (named TeamNameDataDictionary).
